## Open questions

1. **`GET /session/{id}/diff` ships 501 — a scope reduction, recorded here and owed to the backlog.** The plan does not mark `/diff` not-implemented (plan:132) while it explicitly marks `DELETE`, `/fork`, `/revert` (plan:126,134,135), and slice 3 names `/diff` (plan:314). wopr has no pre-message snapshot store, and building one is far outside this slice. The 501 is defensible only because the client treats 501 as not-implemented (plan:147-151). **Action owed: add this deferral, with this reason, to `serve-3`'s entry in `BACKLOG.md`.** The live working-tree `git diff` alternative is rejected: it answers "what is dirty now", not "what this session changed", and the field name claims the latter.
2. **`/permission*` has no owning slice.** `GET /permission` and `POST /session/{id}/permissions/{id}` (plan:143) appear in the 26-path table and in no slice's scope. **Action owed: name them in `BACKLOG.md`,** because the app calls `GET /permission` on session open and an unregistered path 404s, which the client reads as "host gone".
3. **`Session.version` substitutes the build constant for the stated derivation.** The item and the plan both say derive slug *and* version "deterministically from the session ID" (plan:181-183). This spec emits `coding/version.Version` (`"0.2.1"`), which is the truthful meaning of the field but is **not** a derivation from the session ID. (a) Keep the build constant, on the grounds that a version derived from an id would be a value with no meaning; (b) implement the literal derivation — the session file's `header.Version` (`CurrentSessionVersion`, `internal/codingagent/session.go:25`) — which is per-session and 0 on a session written before the field existed. Recommend (a).
4. **`GET /session/{id}/message` is in this slice** even though plan:354-356 assigns message topology to slice 4, because the backlog's gate puts the tail read here and the tail read has exactly one caller. Fallback if overruled: ship `tailEntries` exported, move the handler to serve-4. §5.15.
5. **`slug = id`.** The client requires a stable non-empty string; wopr's id is a UUIDv7, already URL-safe, so `GET /session/{slug}` and `GET /session/{id}` are one request and there is no second resolution path. Alternative: a short hex suffix, which needs `resolveSession` to accept both forms. §3.1.
6. **The item's literal gate text names `BenchmarkServeFanout -benchmem`**; the plan defines that name for the SSE fan-out benchmark (plan:266-271), which is serve-4. This slice ships `BenchmarkServeListRead` and `BenchmarkServeTailRead`. Reconciled, not silently replaced: §6 states the item text verbatim, the plan's definition of that name, and the substitution.

## 1. Layering, and the one edge this slice builds

serve-1 left `serve` importing only `coding/version`, with the `serve -> coding/host` edge
unbuilt. It is built here, by `POST /session`.

```
cmd/wopr/serve.go              -> internal/codingagent/serve, coding, coding/host, internal/codingagent
internal/codingagent/serve     -> coding/host, internal/codingagent, internal/codingagent/sessionblob, tui, coding/version
coding/host                    -> coding, agent, ai, internal/codingagent   (pre-existing)
coding                         -> internal/codingagent                      (pre-existing, services.go:18)
```

`serve` does **not** import `coding` (`coding/services.go:18` already imports
`internal/codingagent`; that would cycle). Two consequences an implementer will hit:

- Every session read goes through `codinghost.Session.Inner()`, a `*coding.Session`, and
  `coding.Session.Inner()`, an `*icodingagent.Session`. `Inner()` always unwraps one layer, so
  the name is consistent in both packages and the transcript types stay reachable. The append path
  (§5.4) uses that second hop for archive, because `AppendCustomEntry` lives on the inner session
  and has no `coding.Session` wrapper — one hop for rename, two for archive, and that asymmetry is
  deliberate, not something to tidy.
- `serve` imports `internal/codingagent` directly, for `SessionHeader`, `SessionEntry`,
  `SessionInfoEntry`, `CustomEntry`, `NewSessionManagerWithDir` and `AuthenticatedProviders`, and
  `internal/codingagent/sessionblob` for `Resolve`. Neither is a new edge: `coding/host` already
  reaches both, and nothing imports `serve`.

**One import alias, pinned: `codinghost "github.com/alexrudloff/wopr/coding/host"`** in every
file of the `serve` package, matching `cmd/wopr/print_mode.go`, which aliases because a parameter
or field named `host` would otherwise capture the selector.

`serve` imports `tui` for exactly one symbol, `tui.FuzzyFilter` (`tui/fuzzy.go:170`), used by
`GET /find/file`. `tui` is a leaf — `go list -deps ./tui` reaches only `internal/text`,
`tui/widthx`, `internal/latex`, `internal/nativeplatform` — and `internal/codingagent` already
depends on it, so this adds nothing to the binary and no cycle.

### 2.2 `func (h *Host) Sessions() []*Session`

A snapshot of the registry under `h.mu.RLock`. Its caller is `GET /session`: a session created by
`POST /session` has **no file on disk** until its first assistant message
(`SessionManager.Create` defers the first write, `internal/codingagent/session_manager.go:88-91`),
so a disk-only list drops the thread the phone just created. The handler unions disk-derived
records with this snapshot, keyed by id.

One line, mirroring `coding.Session.Inner()` (`coding/session.go:897`). The comment at

caller reach `Send` and bypass the run rule" — stays true and gains one sentence: this method is
the deliberate, documented escape hatch for the read surface, and serve never calls `Send` on it.

### 2.4 `StartOptions.SessionDir` and `ErrNoModel`

`var ErrNoModel = errors.New("host: StartOptions.Model is required")` replaces the bare
`errors.New` at `coding/host/host.go:45`. `Start` returns it, serve maps it to 409 with a message

a sentinel in this package.

### 2.5 `func AvailableModels(svcs *coding.Services, current *ai.Model) ([]*ai.Model, error)`

A **rename**, not new code: `rpcAvailableModels` (`coding/host/rpc.go:1178`) gains an exported

### 2.6 `func ModelProviderID(m *ai.Model) string`

Also a **move, not new code**, and it appears **three** times, not two:

```go
// ModelProviderID returns m's provider identity. ProviderMeta.ProviderID can
// legitimately be empty, which is why the provider's own id is the fallback.
func ModelProviderID(m *ai.Model) string {
	if m.ProviderMeta.ProviderID != "" {
		return m.ProviderMeta.ProviderID
	}
	if m.Provider != nil {
		return m.Provider.ID()
	}
	return ""
}
```

The identical two-step is at `coding/host/rpc.go:439-442` (`rpcModelValue`),
`coding/host/rpc.go:661-664` (the `prompt` arm's auth check), and
`coding/host/rpc.go:1210-1213` (`rpcAvailableModels`, folding the provider into a map key).
`AGENTS.md` says fix a wrong function once where every caller routes through, so **all three**
retarget at `ModelProviderID`. Each site keeps its own use of the result, so every one computes
the string it computed before.

`cmd/wopr/serve.go` composes the spec as `ModelProviderID(m) + "/" + m.ID`. `ai.Model.ID` is the
bare id (`ai/types.go:705-717`), so the concatenation is the whole derivation, and `coding`'s own
`providerID` helper (`coding/session.go:783`) is unexported.

### 2.7 `func (sm *SessionManager) AppendCustomEntry(path, customType string, data any) error`

The only genuinely new logic in the slice, and it is the file-level sibling of the method that
already exists beside it:

```go
// RenameSession updates the session name by appending a session_info entry.
func (sm *SessionManager) RenameSession(path, newName string) error
```

(`internal/codingagent/session_manager.go:321-341`, one production caller at
`internal/codingagent/dialog.go:549`). `AppendCustomEntry` is that body with a `CustomEntry{Type:
"custom", CustomType: customType, Data: data}` in place of a `SessionInfoEntry`: same
`os.OpenFile(path, os.O_APPEND|os.O_WRONLY, 0o644)`, same `json.Marshal`, same
`fmt.Fprintf(f, "%s\n", data)`, same error wrapping with the operation named. Roughly fifteen
lines, and it is what makes the archive half of `PATCH` expressible without loading a transcript.

**Why it belongs here rather than in `serve`.** `RenameSession` is the precedent, and a second
append in `serve` would duplicate the open-flag choice, the marshal, the newline framing and the
error wrapping a second time — four things that must agree with `Session.AppendEntry`'s framing or
the file stops being one-record-per-line.

**No `O_CREATE`, deliberately.** `RenameSession` and `AppendCustomEntry` both open
`O_APPEND|O_WRONLY` with no `O_CREATE`, so both **fail on a session with no file**. That is the
invariant §5.4's routing rests on: *cold implies a file exists.* Its one production caller,
`internal/codingagent/dialog.go:549`, is a rename of an existing session and is unaffected by the addition.

**It does not apply `sessionblob.Externalize`.** Neither does `RenameSession`: a `session_info` or
`session_archive` payload carries no image, so there is nothing to externalize, and a custom entry
with an arbitrary `Data any` that *could* contain one is outside this slice's contract. Stated so
nobody adds it "for symmetry".

### 2.8 The session directory: one rule, one function

**The session directory is resolved exactly once, in `cmd/wopr/serve.go`, before `serve.New`, to
an absolute path, and that one value is used by both the read path and the write path.**

```go
// runServeCommand, after settings are built
sessionDir, err := resolveSessionDir("", settings)
if err != nil {
	return failf("wopr serve: %v", err)
}
if sessionDir == "" {
	sessionDir = codingagent.NewSessionManager(cwd).SessionDir()
}
```

**This is one shared function, not two copies of an expression.** Verified by reading both ends:
`defaultSessionDir(cwd)` is defined once, at `internal/codingagent/session_manager.go:49-51`, and
the expression `filepath.Join(AgentDir(), "sessions", encodeCwdForSessionDir(cwd))` exists nowhere
else in the tree. It has **two** callers, not one — `NewSessionManager`
(`internal/codingagent/session_manager.go:32-39`, the assignment is at `:35`) and
`sessionDirIsCwdScoped` (`internal/codingagent/session_resume.go:390`) — and revision 4's "only
in-package caller" was wrong; what matters is that both call the one definition. `coding`'s
`newSessionManagerForDir(cwd, "")` calls `icodingagent.NewSessionManager(cwd)`
(`coding/session.go:610-615`, the call is at `:614`) — it cannot call `defaultSessionDir` directly,
because that symbol is unexported in another package. So the chain is
`newSessionManagerForDir → NewSessionManager → defaultSessionDir`, one definition, two hops. **A
reader must not assume a second copy exists to drift; there is nothing to keep in step, and a
future change to `defaultSessionDir` moves both paths at once.**

`resolveSessionDir` returns `""` for the default configuration — `SettingsManager.GetSessionDir`
(`internal/codingagent/settings.go:1124-1126`) is `normalizeSettingsPath(sm.Get().SessionDir)`,
and `normalizeSettingsPath` returns `""` for an empty path
(`internal/codingagent/settings.go:1204-1207`); `resolveSessionDir` returns it unchanged
(`cmd/wopr/main.go:864-867`) — which is why the fallback is needed at all. Verified: with `""` the
read path's `os.ReadDir("")` fails with `open : no such file or directory`, which is **not**
`fs.ErrNotExist`, so the list would answer 500 rather than empty.

`runServeCommand` has no `--session-dir` flag, so the flag rung of `resolveSessionDir` is
unreachable from serve and the spec passes `""`. Adding the flag is a separate change. The
`*SettingsManager` passed is **serve's own**, the trust-aware
`NewSettingsManagerWithProjectTrust(cwd, agentDir, projectTrusted)` already built at
`cmd/wopr/serve.go:86` — **not** `main.go`'s project-trust-blind `startupSettingsManager`
(`cmd/wopr/main.go:355`), because a served session directory is a project-scoped setting and serve
has already resolved project trust.

`cmd/wopr/serve.go` passes **the same `agentDir`** to `NewServices` that `codingagent.AgentDir()`
returned, so `Services.AgentDir()` and `defaultSessionDir`'s use of `AgentDir()` cannot disagree.
Without that line, the two would read different roots.

`NewSessionManager` also calls `sessionblob.SweepDaily` on the default path. That is the same sweep
the CLI performs whenever it builds a manager; it now happens once at server start instead of once
per first session, and it is why serve needs no separate sweep.

The resolved value is handed to `serve.New`, which passes it to its own file reader (§4) **and** to
`Host.StartOptions.SessionDir` (§2.4). **There is no other place in this slice that resolves a
session directory.** §4.5's root and §5.6's `directory` come from `Services.CWD()`, which is the
working directory, a different thing.

### 2.9 Nothing else changes

`Host.Start`, the one-run rule, `Bus`, `Subscription`, `Event`, and `New`'s signature are untouched.

left it as open question 5; the ruling round checked the append path against both `PATCH` bodies

## 3. DTOs

Every response is the bare object or array, not an envelope — `serve`'s existing
`healthResponse` already establishes that. The blocks below are gofmt-formatted; run `gofmt`
after pasting them rather than trusting the alignment here.

Every field of plan:170-179 is emitted. Beyond that table this slice emits **nothing it does not
itself derive**, which is why `Session.parentID` and `AgentInfo.description` are absent: neither

### 3.1 Session

```go
type sessionDTO struct {
	ID        string         `json:"id"`
	Slug      string         `json:"slug"`
	ProjectID string         `json:"projectID"`
	Directory string         `json:"directory"`
	Title     string         `json:"title"`
	Version   string         `json:"version"`
	Time      sessionTime    `json:"time"`
	Tokens    *sessionTokens `json:"tokens,omitempty"`
	Cost      *float64       `json:"cost,omitempty"`
}

type sessionTime struct {
	Created  int64  `json:"created"`
	Updated  int64  `json:"updated"`
	Archived *int64 `json:"archived,omitempty"`
}

type sessionTokens struct {
	Input  int        `json:"input"`
	Output int        `json:"output"`
	Cache  tokenCache `json:"cache"`
}

type tokenCache struct {
	Read  int `json:"read"`
	Write int `json:"write"`
}
```

**`slug`** = the session id. Open question 5.

**`version`** = `coding/version.Version`. A substitution for the item's stated "derive
deterministically from the session ID", recorded as open question 3.

**`projectID`** = the first 12 hex characters of `sha256(resolvedProjectRoot)`, from one helper
`projectID(root string) string` shared with `GET /project` (§5.6), so `Session.projectID` and
`Project.id` cannot drift.

**`directory`** = **the session's own `header.CWD` when non-empty, otherwise the server's resolved
root.** plan:175 lists it as required. The session's own cwd is the truthful value: a session
resumed from another directory reports the directory it was created in, which is what the client's
session list groups by. `header.CWD` comes from the header line the metadata reader already parses
(§4.1), so this costs nothing.

**Its interaction with the `directory` query parameter.** The request parameter is validated
against the **server root** (`EvalSymlinks(Services.CWD())`), never against `Session.directory`
(§5 preamble). A client that echoes a session's own `directory` back — which plan:129 has it do on
`POST /session/{id}/prompt_async` — therefore gets **400** for a session created elsewhere, and
that is the correct answer: the server genuinely cannot serve a second working directory
(plan:346), and answering 200 while reading the wrong tree would be worse. For every session
created by this server the two values are equal and the echo succeeds.

**`time.created`** = the header's `timestamp` parsed as RFC3339Nano, epoch millis.
**`time.updated`** = the session file's mtime, epoch millis. A live session with no file yet has no
mtime, so it inherits `Created` rather than a fabricated value.

**`title`** = the newest `session_info` entry's `Name`, else the first user message's text
truncated to 200 characters, else `""`. **`time.archived`** = the newest `custom` entry with
`customType == "session_archive"`. Both are read by the single metadata reader (§4.2), which has
one rule for every session. `SessionInfoEntry` has **only** a `Name` field, so archive is *not*
carried by `session_info`; it is a `custom` entry, read back by `customType` (§5.4).

**`tokens` / `cost`** come from `icodingagent.Session.Accounting()`
(`internal/codingagent/session_stats.go:106`), maintained incrementally as entries are appended.
Emitted **only** for a session live in the host registry. A session read from disk has no
accounting without a whole-file decode, which is the read this slice exists to avoid, so both are
omitted there — never zero. `Cost` is additionally omitted when
`Accounting().Tokens.CostUnknown` is set (`internal/codingagent/session_stats.go:22-24`): those amounts are unknown,
not free.

`tokens.reasoning` is **not** emitted. `ai.Usage.Reasoning` exists (`ai/types.go:339`) but
`SessionTokenStats` does not accumulate it, so there is no truthful value to send and `0` would
read as "no reasoning tokens".

## 4. The readers

**There are exactly two ways this slice touches a session file, and one backward primitive behind
both.**

```
walkBack(path, stop) ──┬── sessionMeta   (stop: newest session_info + newest session_archive)
                       └── tailEntries   (stop: limit+1 complete records)
```

Neither path calls `loadSessionFile`, `summarizeSessionFile`, `SessionManager.ListSessions`, or
`SessionManager.FindByID`; `FindByID` in particular calls `ListSessions` → `summarizeSessionFiles`,
which retains `AllMessagesText` for every session in the directory
(`internal/codingagent/session_resume.go:40,289,337`).

### 4.1 `walkBack(path string, stop walkStop) ([][]byte, error)` — the one primitive

Open the file, `Seek(0, io.SeekEnd)`, then walk backwards in `tailBlockBytes = 64 KiB` blocks
until `stop` is satisfied or `maxTailBytes = 16 MiB` is reached. Chunks are collected into a
`[][]byte` in read order and joined **once** — prepending block by block is O(n²) in blocks.
Whatever comes back, everything through the first `\n` is dropped, because the first block is a
partial record, and the remainder is split on `\n` into record byte slices, oldest-first.

Splitting on `\n` is safe, and the reason is one seam, not two. **`appendSessionLine` and
`writeSessionLines` never encode anything** — they `Fprintf` bytes that were already encoded. The
real seam is `marshalJSONLine` (`internal/codingagent/session_export.go:26-34`), which every
append goes through (`Session.AppendEntry` → `marshalJSONLine`, `internal/codingagent/session.go:485`)
and which uses `json.Encoder`; the derived-session writer uses `json.Marshal`
(`internal/codingagent/session_manager.go:236`). Both escape `\n` inside JSON strings, so no
written record contains a raw newline. The plan confirms the read is implementable for this reason
(plan:62-63).

`walkStop` is one of:

| caller | satisfied when | bound |
|---|---|---|
| `sessionMeta` | the newest `session_info` **and** the newest `custom` entry with `customType == "session_archive"` have both been seen, **or** the file's head is reached | `metaProbeBytes = 32 << 10` |
| `tailEntries` | `limit+1` complete records are held | `maxTailBytes = 16 << 20` |

Decoding uses `icodingagent.SessionEntryBase` only, so a malformed record is skipped rather than
failing the request — the same tolerance `loadSessionFile` applies
(`internal/codingagent/session_manager.go:151-154`). A file whose **first** line is not a
`type: "session"` header is a 404, matching what `loadSessionFile` rejects. `sessionMeta` never
resolves blobs: `session_info` and `custom` records never carry images, and resolving them would
inline megabytes to read a name.

### 4.2 The metadata reader — `sessionPath`, `sessionRecordAt`, `sessionRecord`

Three functions, each with a named caller and no duplicated logic:

```go
// sessionPath maps a session id to its transcript file in dir. Session files are
// named <timestamp>_<id>.jsonl, so filepath.Join(dir, id+".jsonl") never matches:
// the timestamp prefix is part of the name. This is a bounded suffix match over
// one already-resolved directory.
func sessionPath(dir, id string) (string, bool)

// sessionRecordAt reads the metadata Branch A needs from a known file.
func sessionRecordAt(path string) (sessionRecord, bool)

// sessionRecord is the id-addressed front door. live is the host's wrapped
// session when it owns one, and nil otherwise; it is what makes Branch B
// reachable, because Branch B reads a *coding.Session that an id cannot yield.
func sessionRecord(dir, id string, live *codinghost.Session) (sessionRecord, bool)
```

**The id→path rule.** Two steps, and neither is a pattern:

```go
var sessionIDPattern = regexp.MustCompile(`^[A-Za-z0-9-]{1,64}$`)

func sessionPath(dir, id string) (string, bool) {
	if !sessionIDPattern.MatchString(id) {
		return "", false
	}
	entries, err := os.ReadDir(dir)
	if err != nil {
		return "", false
	}
	suffix := "_" + id + ".jsonl"
	for _, entry := range entries {
		if name := entry.Name(); !entry.IsDir() && strings.HasSuffix(name, suffix) {
			return filepath.Join(dir, name), true
		}
	}
	return "", false
}
```

**Why not `filepath.Glob`, which revision 4 specified and which was wrong.** Revision 4 claimed
`filepath.Glob(filepath.Join(dir, "*_"+id+".jsonl"))` "cannot escape `dir`" because `*` does not
cross a separator. That is true of the `*` and false of `dir`, which is interpolated into the
**pattern** unescaped. Measured on this host against a directory tree holding one real transcript
and one decoy:

| `dir` | result |
|---|---|
| `/tmp/…/real` | 1 match — correct |
| `/tmp/…/*` (a project path containing `*`) | **2 matches** — the real transcript *and* a decoy project's |
| `/tmp/…/brack[1]` | **0 matches** — every lookup silently 404s |
| `/tmp/…/trail[` | `syntax error in pattern`, and `sessionPath`'s signature has nowhere to put an error |

None of those inputs is hypothetical: `encodeCwdForSessionDir`
(`internal/codingagent/session_manager.go:64-71`) replaces only `/`, `\` and `:`, so `*`, `?` and
`[` survive into a real session directory name, and `EvalSymlinks` does not strip them. A reader
that walked into a neighbouring project's session directory would be a cross-project transcript read
on an auth-less LAN server — the one thing `resolveInRoot` (§4.5) exists to prevent.

**The property the new rule actually has.** `dir` is never interpreted as a pattern: it is the
argument to `os.ReadDir`, which reads exactly that one directory and does no matching at all. The
only variable part of the comparison is `id`, and the character class `[A-Za-z0-9-]` gives it no
path meaning — no separator, no `.`, no glob character — so `suffix` cannot match a name outside
the directory that `ReadDir` just listed. That is a stronger statement than "the glob stays inside
`dir`", and it is the one to hold this code to.

**The id validation stays, and it is what makes the suffix safe to interpolate.** Measured
independently: `[A-Za-z0-9-]{1,64}` rejects `*`, `?`, `[`, `\`, the empty string, an over-length
id, and `../etc`. It is a trust-boundary check, not a formality — the id is a URL path segment.

**The suffix match identifies exactly one name.** The `<timestamp>_<id>.jsonl` shape is fixed by
`SessionManager.Create` (`internal/codingagent/session_manager.go:84`, with `fileTimestamp` at
`:104-108` replacing `:` and `.` with `-`) and by `writeDerivedSession` (`:229`). The timestamp
prefix contains no `_` and a UUIDv7 id contains no `_`, so `"_" + id + ".jsonl"` identifies one
name. Two matches would mean a corrupt directory; the first in `ReadDir` order is taken and the
case is named in a comment rather than given an error path for a state the writer cannot produce.

**The cost, stated honestly: one `os.ReadDir` per id-addressed request.** No map is cached, and
deliberately so. The alternative — a `map[id]path` built once by `GET /session` and handed to the
other three routes — trades a `ReadDir` for a staleness bug: a session created after the map was
built would 404 on `GET /session/{id}`, `PATCH` and `/message`, and the phone's own
`POST /session` → `GET /session/{id}` sequence is exactly that sequence. Against the slice's
bounded-read thesis a `ReadDir` is cheap and, importantly, **it reads no file contents** — it
returns one name and type per entry. `GET /session` already pays a `Stat` per listed session for
mtime (§5.1), so this is strictly less work than a single list page, and it is bounded by the
number of files in one directory rather than by any transcript's size.

**How the directory reaches the reader.** `serve.New(addr, h, sessionDir, model)` stores
`sessionDir` on the server struct next to `h`, and **every id-addressed handler passes it**:
`GET /session/{id}`, `PATCH /session/{id}`, `GET /session/{id}/todo` and
`GET /session/{id}/message`. Revision 4 declared `sessionRecord(id string)` with no directory and
no `Path` source, which left all four of those routes unwired; the directory is §2.8's one
resolved value, handed in once and never re-derived.

**Where `Path` comes from.** Branch A sets it from the path it was given. Branch B sets it from
`live.Inner().Path()`, which is **non-empty even when no file exists yet** — `Create` assigns
`sess.path` before the first write is deferred (`:86` against `:88-91`) — so `Path` alone cannot
select the branch. `HasFile` is `false` when `os.Stat(live.Inner().Path())` reports
`fs.ErrNotExist`, and that is the branch condition.

**Branch selection, stated once.**

| `live` | `HasFile` | branch | source of every field |
|---|---|---|---|
| non-nil | false | **B** — in memory, no read | `live.Inner().Header()`, then a `slices.Backward` scan of `live.Inner().Entries()` |
| non-nil | true | **A** | `sessionRecordAt(live.Inner().Path())` |
| nil | — | **A** | `sessionRecordAt(sessionPath(dir, id))`, or a miss |

```go
type sessionRecord struct {
	ID       string
	Header   icodingagent.SessionHeader
	Name     string
	Archived *int64
	Path     string
	ModTime  time.Time
	HasFile  bool
}
```

**Branch A — the session has a file.** `os.Stat` for mtime, read line 1 as the header, then
`walkBack` with the `sessionMeta` stop. The last `session_info` record sets `Name`; the last
`custom` record with `customType == "session_archive"` sets `Archived`.

**Branch B — the session is live and has no file yet** (created by `POST /session`, deferred first
write). No read at all: `Header` from `live.Inner().Header()`, then a `slices.Backward` scan of
`live.Inner().Entries()` for the same two record shapes, decoding only the raws it visits.
`ModTime` is zero, so `time.updated` falls back to `Created` (§3.1).

**Why the two branches cannot disagree.** `Session.AppendEntry` appends to memory and disk in the
same call (`internal/codingagent/session.go:501-562`), and defers only the *first* disk write until
an assistant message arrives — which is exactly the condition that selects Branch B.

**The head read survives for one reason only.** The title fallback — the first user message — is
near the *start* of the file, so it cannot come from `walkBack`. It is a separate, bounded
`titleProbeBytes = 8 << 10` read from the head, and it runs **only when `sessionMeta` found no
name**. A renamed session costs one 32 KiB backward read; an un-renamed one that plus 8 KiB. Worst
case per listed session is 40 KiB, against `limit` ≤ 200.

**The residual, rescoped.** `Name` and `Archived` are read from the **tail**, and `PATCH` writes
them at the **tail** (§5.4), so the record a `PATCH` just appended is by construction the last
record in the file and is always inside the bound. **The A2 oracle therefore cannot be violated by
this bound, and the revision-3 caveat that a `PATCH` response may disagree with a later read is
deleted, not softened.**

What survives is one narrower case, about *old* markers: a `session_info` or `session_archive`
record written more than 32 KiB **before the end** of the file is not seen, so a session renamed or
archived long ago and then grown past the bound reports no name and falls back to its first user
message. `walkStop` also stops at the head, so a file smaller than the bound always finds its
marker. This is in §8 and §7's not-proven list.

### 4.3 `tailEntries(path string, limit int) ([]icodingagent.SessionEntry, error)`

`walkBack` with the `limit+1` stop, then the last `limit` records, returned oldest-first. For each
record: **resolve the line bytes, then decode** — `sessionblob.Resolve(path, line)` first, then
`json.Unmarshal` into `SessionEntryBase`. That order is load-bearing: `Resolve` is
`func(sessionPath string, line []byte) []byte`
(`internal/codingagent/sessionblob/sessionblob.go:73`), it works on bytes and cannot touch a decoded
entry, and the only existing caller resolves before unmarshalling
(`internal/codingagent/session_manager.go:150-151`). It is also what makes §4.4's budget
measurable, because the budget sizes `data`.

When the session is live but has no file, `tailEntries` is skipped and the last `limit` entries come
from `Session.Entries()`. `Entries()` copies the whole slice
(`internal/codingagent/session.go:411-416`), which is why the file path is preferred whenever it
exists.

### 4.4 Window-scoped blob resolution

`loadSessionFile` applies `sessionblob.Resolve` to every entry so blob-externalized images come
back inline; revision 2's tail read silently dropped that step, so an image in the served window
would have decoded as `{"blob":"<id>"}` with no data.

The tail read applies it to each record in its window, and **the window is the bound**: only the
last `limit` entries are decoded, which is exactly plan:258-260's "blobs resolve only inside the
served window" — 50 phone photos in a session do not become 50 decoded images to render the last
20 messages.

Resolution is additionally capped, because the JSONL byte cap does not bound it: the blob files
are read outside `maxTailBytes`. `maxInlinedImageBytes = 8 << 20` per response, decremented by
`len` of each **resolved** record before it is decoded. A record that would exceed the remaining
budget is emitted as a `text` part reading `[image omitted: budget exceeded]`, matching the wording
`sessionblob.Resolve` already uses for a blob it cannot read (`[image missing: <id>]`,
`internal/codingagent/sessionblob/sessionblob.go:85`), so there is one convention for "no image
here".

### 4.5 `resolveInRoot(root, want string) (string, error)`

About fifteen lines:

```go
// resolveInRoot resolves want against root, refusing anything that leaves it.
// Symlinks are resolved on both sides first, so a link out of the project is a
// refusal rather than a read.
func resolveInRoot(root, want string) (string, error)
```

`root` is `EvalSymlinks(services.CWD())` — the **working** directory, not the transcript directory
of §2.8. **A missing path and a forbidden path are different answers, and the caller must be able to
tell them apart**, because the client branches on 404 (plan:147-148). So the helper distinguishes
three outcomes rather than collapsing a failed `EvalSymlinks` into one refusal:

1. `cleaned` = `filepath.Clean(want)` with any leading `/` stripped, so `../../etc/passwd` becomes a
   relative path and an absolute `want` is treated as root-relative, never as absolute.
2. `candidate = filepath.Join(root, cleaned)`. `os.Lstat(candidate)` reporting `fs.ErrNotExist` →
   **absent**; the handler answers **404**. This `Lstat` is the whole fix: it separates "no such
   file" from "a link that does not resolve", which revision 4 conflated.
3. Otherwise `EvalSymlinks(candidate)`. A failure now means a **broken or unreadable link**, not an
   absent path, so it is **403**. On success, `filepath.Rel(root, resolved)`; a `..` element or a
   `..`-prefixed result means the resolved target is **outside the root**, so it is **403**.

`EvalSymlinks` on both sides is what makes a symlink out of the project a refusal rather than a
read, and it is why step 2 uses `Lstat` (which does not follow the link) rather than `Stat`.

This ships in serve-3, not serve-5, because of the standing backlog constraint: "the path allowlist
on resolved paths is what makes auth-less LAN serving defensible, so it ships before or with the
file endpoints, not after" (`BACKLOG.md:28-30`). serve-5 applies the same helper to
`GET /file/content`.

## 5. Handlers — 19 new routes, 15 new functions (20 and 16 with `health`)

```go
func New(addr string, h *codinghost.Host, sessionDir, model string) (*http.Server, net.Listener, error)
```

The signature changes, touching exactly two call sites (`cmd/wopr/serve.go`, `serve_test.go`).

`writeJSON(w, status, v)` sets `Content-Type: application/json`, calls `w.WriteHeader(status)`, and
encodes with `SetEscapeHTML(false)` — the rule at `cmd/wopr/rpc_types.go:23-29`, because session
titles, message text and file names reach this wire and routinely contain `&`, `<`, `>`. `health`
moves onto it: revision 2 left the existing handler on its own `json.NewEncoder`, which is two
write paths in one package and a split the DoD grep could not see.

`http.MaxBytesReader` wraps every body-carrying handler at `maxBodyBytes = 16 << 20`, the size the
plan justifies at plan:218-223. Errors are `errorDTO` with the status below.

`limitOf(r, def, max)` parses `limit`; a non-integer or negative value is `def`, and anything above
`max` is clamped. A `directory` parameter that is present and differs from the server's **resolved
root** is a **400** — never compared against `Session.directory` (§3.1). The parameter must be
*answered*, not ignored.

**Request headers, reconciled with plan:160-162.** `Accept` on a REST route asks for JSON and the
server always answers JSON, so it is accepted and never negotiated — one representation per route.
`Cache-Control` is a request header whose purpose is the SSE stream, which is serve-4's; no JSON
route in this slice reads it. The two that reach the server as response-relevant are answered:
every route sets `Content-Type: application/json`, and no JSON route sets `Cache-Control`, so the
client's no-cache request cannot be contradicted by a cached response.

### 5.1 `GET /session` — 200, `[]sessionDTO`

`limit` default 50, max 200. `directory` as above. The directory enumerated is the one resolved by
§2.8 — the same absolute path `Host.Start` writes to, with no second resolution.

Union of `sessionRecordAt(path)` over every `*.jsonl` in that directory (§4.2) and `h.Sessions()`
(§2.2), keyed by the header id each file yields, disk first, sorted **once** in the handler on `(mtime desc, header timestamp desc,
path asc)` — the key order `compareSessionRecencyDesc` documents
(`internal/codingagent/session_resume.go:139-145`), written out locally since the comparator is
unexported — then truncated to `limit` after the union. `tokens`/`cost` only on the registry
entries. The reader returns unsorted; revision 2 sorted in both the reader and the handler, which is
dead work.

### 5.2 `POST /session` — 200, `sessionDTO`; 409 when no model is configured; 500 otherwise

Body ignored (the client sends none). Calls `h.Start(codinghost.StartOptions{Model: model,
SessionDir: sessionDir})`.

| outcome | status | body |
|---|---|---|
| `errors.Is(err, codinghost.ErrNoModel)` | **409** | "no model is configured for this server; start it with `wopr serve` after setting a default model (`wopr --model <provider/model> <prompt>`, or `settings.defaultModel`)" |
| any other `Start` error | **500** | `err.Error()` |

Only `ErrNoModel` is a configuration signal the user can act on from the request; a `BuildModel`
failure inside `Start` is a server-side derivation or state fault and is a 500. `POST /session` is
the one route where this is decided — `selectStartupModel` runs in `cmd/wopr/serve.go` *before*
`serve.New` exists and therefore cannot answer anything.

### 5.3 `GET /session/{id}` — 200, `sessionDTO` / 404

`sessionRecord(sessionDir, id, h.Get(id))` — the id front door of §4.2, with the host's own lookup
already evaluated, which is what makes Branch B reachable for a session this process created. It is
a **lookup, not an adoption**: the two branches read a file or the in-memory entries and neither
loads anything new. So the read path
stays bounded: no route here calls `loadSessionFile`, and no route here adds the session to the
host. A registry hit contributes `tokens` and `cost` on top of the record; every other field comes
from the record, which is the same reader for live and non-live sessions, so §3.1's "one rule"
holds without a second source.

404 with `errorDTO` when neither finds it: the status the client branches on for "session or host
gone" (plan:147-149).

### 5.4 `PATCH /session/{id}` — 200, `sessionDTO` / 400 / 404 / 500

**The rule: both bodies are one appended record, and the response is the metadata reader's output
after that append. No transcript is ever loaded, and no session is ever adopted into the host.**

That is what withdrew `Host.Resume`. A rename is a `session_info` record; an archive is a
`session_archive` `custom` record; both are appended at the **tail**; and the metadata reader
already reads the tail for exactly those two shapes (§4.2). `RenameSession` was already exported
for the first (`internal/codingagent/session_manager.go:321`), and §2.7 adds its sibling for the
second.

**Routing.** The invariant that makes this unambiguous is §2.7's: both file-level appends open
`O_APPEND|O_WRONLY` with **no `O_CREATE`**, so they fail on a session with no file. A session with
no file can only be one this process created, and only such a session is in the registry. Therefore
**live implies the host owns it, and cold implies a file exists**, and the write path is decided by
`h.Get(id)` alone:

| case | write | why |
|---|---|---|
| `h.Get(id)` hits | `session.Inner().SetSessionName(title)` / `session.Inner().Inner().AppendCustomEntry("session_archive", …)` | a live session has buffered entries and an in-memory entry list that must stay consistent with the file. A direct file append would write a record the session does not know about, so `Entries()` would not see it and the next `AppendEntry` would parent onto a stale leaf. **That is a lost update, not a style preference.** |
| `h.Get(id)` misses, `sessionRecord(sessionDir, id, nil)` hits | `sm.RenameSession(path, title)` / `sm.AppendCustomEntry(path, "session_archive", …)` | nothing else owns this file. wopr's rule is that a session file is append-only and only its owning `Session` appends to it; there is no owner here, and the two file-level appends are that mechanism. |
| neither | **404** | |

`sm` is a `*icodingagent.SessionManager` built once in `serve.New` as
`icodingagent.NewSessionManagerWithDir(services.CWD(), sessionDir)` — `NewSessionManagerWithDir`
(`internal/codingagent/session_manager.go:44-46`) stores the dir verbatim and calls **no**
`sessionblob.SweepDaily`, which is why serve uses it rather than `NewSessionManager`; the default
path's sweep already happened once in `cmd/wopr` (§2.8).

**Concurrency, case by case.**

- Two `PATCH`es on one **live** session both reach `Session.AppendEntry`, which holds `s.mu` across
  the stats update, the slice append, the `byID` insert and the leaf move
  (`internal/codingagent/session.go:501-536`), so the in-memory list is serialised and last
  writer's name wins, which is the correct rename semantic.
- **The file write is protected by `O_APPEND`, not by a mutex.** `s.mu` is released at
  `internal/codingagent/session.go:537`, *before* the disk write at `:539-562`, and
  `appendSessionLine` (`:567`) opens `os.O_APPEND|os.O_CREATE|os.O_WRONLY`. So the live and cold
  cases share one mechanism, and it is the same one the cold bullet below relies on.
- **`leafAppendMu` is not on the rename path, and does not need to be.**
  `coding.Session.SetSessionName` calls `s.inner.AppendEntry` directly
  (`coding/session.go:967-983`) without taking it; `leafAppendMu` is held only by `appendOnLeaf`
  (`internal/codingagent/session.go:622-623`), the helper behind `AppendMessage` and
  `Session.AppendCustomEntry`. So a rename concurrent with an ordinary append can parent its
  `session_info` record on a leaf that is no longer the newest. No reader in this slice consults the
  parent chain — `sessionMeta` scans records by type, newest-last — so the effect is unobservable
  here, and stating it is cheaper than claiming a lock that is not held.
- Two `PATCH`es on one **cold** session each perform one `fmt.Fprintf` of one complete line to a
  handle opened `O_APPEND`. The kernel positions each write at end-of-file atomically, so two
  concurrent renames produce two whole records in some order, never a torn line, and the reader's
  "last `session_info` wins" resolves them.
- A **cold** session cannot become **live** during a `PATCH`. `Host.Start` mints a fresh UUIDv7 and
  never adopts an existing file, and this slice has no adoption method (§2.9), so there is no third
  writer to interleave with and no check-then-act window to lose.
- `sessionblob.SweepDaily` and `DeleteSession`'s blob sweep
  (`internal/codingagent/session_manager.go:316`) touch blobs, not `.jsonl` records, and
  `DeleteSession` has no route in this slice.

**Bodies.** Two shapes, discriminated by which pointer is set:

```go
var body struct {
	Title *string `json:"title"`
	Time  *struct {
		Archived *int64 `json:"archived"`
	} `json:"time"`
}
```

- `Title` set and non-empty → append the `session_info` record. **Both error returns are
  assigned**: a failed append is **500** with its text, never a dropped value. An empty or
  whitespace-only title is a **400**; `SetSessionName`'s own comment says every boundary validates
  non-empty input first, and `RenameSession` does not, so the handler must.
- `Time` set → archive. `Archived` non-nil records that epoch-ms value; absent or `null` clears it,
  by appending a `session_archive` record carrying the cleared state — the newest record wins, so
  "clear" is a value, not a deletion.
- Both set → **400**. Neither set → **400**.

**The 200 response, and the oracle.** The handler re-runs
`sessionRecord(sessionDir, id, live)` after the append — passing the **same** `live` value it
routed on, so the live case reads Branch B and the cold case reads Branch A — and builds the full
`sessionDTO` from that record (plus `tokens`/`cost` when live). A subsequent `GET /session/{id}`
runs the same reader with the same `h.Get(id)`. They agree by construction rather than by
coincidence,
and `TestPatchThenGetAgrees` (§6) asserts it in both reachable states. Revision 2 left this the only
route whose statuses had no body, leaving the implementer to invent it, and told the implementer to
read the write back from the **head** probe — which cannot see a tail append for any session over
64 KiB, making archive write-only, and cannot see it at all for a live session with no file.

**Two shapes that look like a mismatch and are not.** `coding.Session.SetSessionName` parents the
`session_info` record on the current leaf; `SessionManager.RenameSession` leaves `ParentID` nil,
i.e. the documented root form `"parentId": null`
(`internal/codingagent/session.go:49-52`). Both are legal and the reader decodes only
`SessionEntryBase`, so it does not care. **Do not "fix" one to match the other** — a root
`session_info` is exactly what `internal/codingagent/dialog.go:549` has always written.

### 5.12 `GET /file?path=&directory=` — 200 `[]fileNodeDTO`; 400 / 403 / 404

`path` defaults to the project root. Every candidate goes through the allowlist (§4.5). Then:

- the resolved path is a **regular file** → **400**, saying `path` must name a directory, rather
  than letting `os.ReadDir` on a file surface as a 500 from a syscall error;
- otherwise one `os.ReadDir`, `type` from `DirEntry.IsDir()`, sorted by name, truncated to
  `maxFileEntries = 500`.

The 404 and 403 are **not decided here** — they come from `resolveInRoot` (§4.5), which `Lstat`s
first so that an absent path is 404 and only a path that resolves outside the root, or whose link
does not resolve, is 403. Revision 4 also listed a 404 branch in this handler, which was
unreachable under §4.5's then-current rule that every failed `EvalSymlinks` was a 403; the branch
is gone and the helper is the single place the distinction is made.

`path` is echoed relative to the root, slash-separated, so the client never learns the absolute
prefix from this endpoint.

### 5.13 `GET /find/file?query=&limit=` — 200, `[]fileNodeDTO`

`filepath.WalkDir` from the root, skipping `.git`, `node_modules`, and dot-directories, capped at
`maxWalkEntries = 20000` visited paths. Candidates are `tui.FuzzyFilter`ed on their root-relative
path, then truncated to `limit` (default 50, max 100). An empty `query` returns the first `limit`
paths in walk order — a plain file browser, which is what the app's file panel shows before a
character is typed.

### 5.14 `GET /file/status` — 200, `[]fileStatusDTO`

`workingTreePaths(root)` in `serve_read.go`, ~20 lines, self-contained. It runs

```
git -C <root> status --porcelain=v2 -z
```

and parses the **NUL-separated** form. Revision 2 proposed extending `parseGitStatusV2` instead, on
the theory that reuse was cheaper. It is not, and the reason is measured.

**Three facts make the `-z` form parseable with one rule. They were verified on this host against a
scratch repository holding a modification, a rename, an untracked file, and a file whose name has
both a space and a non-ASCII byte. Do not "simplify" this back to `strings.Fields` with a fixed
index — that is the specific mistake this section exists to prevent, because it yields *wrong
paths*, not missing ones.**

1. **The path is the last space-separated field for `1`, `2` and `u` alike.** The four prefixes do
   *not* share an index: `1 <XY> <sub> <mH> <mI> <mW> <hH> <hI> <path>` puts it at index 8;
   `2 <XY> <sub> <mH> <mI> <mW> <hH> <hI> <X><score> <path><TAB><origPath>` puts it at index 8 of
   the space split **and a second path after a TAB**; `u ` carries 11 fields with the path at index
   10; `? ` has it at index 1. "Last field" collapses three of the four; the rule below handles the
   fourth.
2. **A rename's original path arrives as a separate record that must be skipped.** Under `-z` a `2`
   record is followed by one extra NUL-terminated record holding the original path. Measured:
   `2 R. … R100 renamed.txt` then `gone.txt`. That second record is not a status line and must be
   consumed by the `2` arm, not read as a path of its own.
3. **`-z` emits unquoted bytes.** In the line form a path with a space or a non-ASCII byte comes
   back C-quoted and octal-escaped — measured, `? "uni \303\251.txt"` — which would need a
   C-unescaper Go's standard library does not have. Under `-z` the same file yields
   `? uni é.txt`. This is the fact that makes the parser twenty lines instead of a quoting
   library.

The rule, in full:

1. Split stdout on `\0`; drop the trailing empty record.
2. For each record, dispatch on its first byte:
   - `'1'` → path = last space-separated field. Emit.
   - `'2'` → path = last space-separated field. Emit. **Then skip the next record**, which is the
     original path.
   - `'u'` → path = last space-separated field. Emit.
   - `'?'` → path = the record after `? `. Emit.
   - anything else → skip.

A rename is therefore **one** DTO entry, carrying the destination path. The DTO has no second field
for the source, `/file/status` is a changed-file list, and this keeps the entry count equal to the
count `parseGitStatusV2`'s `changed++` already computes — which revision 2's two-paths-per-rename
proposal would have doubled.

Truncated to `maxFileStatusEntries = 500`, the same bound as `GET /file` — revision 2 capped two
file routes and left this one uncapped on an unauthenticated LAN socket. Empty slice outside a git
work tree, because the command exits non-zero there; the test fixture is a temp `CWD` (§6), so that
is a state a test can actually produce, and one that asserts it.

This is a **second** `git status` invocation alongside the sidebar's `readGitSummary`, and that is
deliberate: `wopr serve` has no sidebar, so the two never run in one process. Reusing
`parseGitStatusV2` would have meant either a per-prefix field-index table plus a C-unescaper, or
changing `-z` handling in TUI code to serve a server. `internal/codingagent/sidebar_data.go` is
untouched and `summary.changed` is unaffected by construction.

### 5.15 `GET /session/{id}/message?limit=` — 200, `[]messageDTO` / 404

`limit` default 50, max 200, oldest-first within the window.
`sessionRecord(sessionDir, id, h.Get(id))` first, so a stale id is a 404 and never an empty array; then `tailEntries` over the session's file, or
`Session.Entries()` when it has none (§4.3), then the part mapping of §3.2 with the blob budget of
§4.4. This is the route whose presence is open question 4.

## 7. Wire verification, and what it does not prove

**serve-2's three-arm byte-identity probe is deliberately not ported.** Revision 1 ported it
mechanically and it could not have paid off: `POST /session` and `PATCH` mint a fresh UUID and a
fresh `time.created` per arm, so "curl every route" is nondeterministic by construction; a fresh
temp `WOPR_HOME` contains no session files, so `GET /session` is `[]` and the metadata reader never
runs; and there is no old binary to diff against, because every one of these endpoints is new. The
`~/bin/opencode` cross-check is also dropped: that wrapper requires `-u opencode:<password>` against
the LAN host and otherwise launches a local opencode, so it is neither hermetic nor available.

**What this slice collects instead.**

1. **Per-DTO client-shaped decodes** (§6). Every required field of plan:170-179 is emitted and
   decodes into a non-pointer field.
2. **A status test per route family**, through the same `newTestServer`, covering each documented
   status the fixture can actually reach — including `POST /session` **200**, which
   `WOPR_TEST_FAUX=1` makes reachable.
3. **`TestRequestBodyFieldsAreBuiltins`**, and `TestPatchThenGetAgrees` for the write/read
   coherence the §5.4 oracle requires.

**On the `<pkg>.<Type>` trap, stated accurately.** Revision 2's rationale was unsupported: it
claimed the DTOs decode into structs embedding `codingagent.SessionHeader`, and none of §3's DTOs
embeds anything — `sessionDTO` is flat, and header decoding is internal to the metadata reader. The
real mechanism, measured rather than assumed: `encoding/json` prints `UnmarshalTypeError.Struct`
with `Struct.Name()` — the type name, never the package — and only prints a package qualifier
through `Type.String()`, which fires when the *field's* type is a named non-builtin type. Decoding
`{"sub":7}` into a struct with a `partDTO` field produces `… into Go struct field namedPkg.sub of
type main.partDTO`; decoding `{"title":7}` into an all-builtin inline struct produces `… struct
field .title of type string`, for every input.

So **serve-3 is not exposed as specified**: its only request body is `PATCH /session/{id}`, decoded
into an all-builtin struct, and its only decodes of external data are into `SessionHeader`,
`SessionEntryBase`, `MessageEntry`, `SessionInfoEntry` and `CustomEntry` — none of which is reached
by a *request*. No type is moved or renamed across a package boundary in this slice. **The exposure
is the next request body with a named-typed field**, and the rule is: that handler must either keep
its fields builtin or adopt the `unmarshalRPC` rewrite `coding/host/rpc.go:396-402` already carries
for the same reason. `TestRequestBodyFieldsAreBuiltins` is the gate that keeps it unreachable
today; revision 2's grep could not, because it enumerated five qualifiers and missed `main.`.

**The narrow, true version of revision 1's claim about the RPC tests.** Revision 1 wrote "zero test
files assert response text", and that is false: `TestRPCContract` (`cmd/wopr/rpc_mode_test.go:194`)
asserts response *values* — `model["provider"] == "test-faux"`, `data["exitCode"]`, message roles,
reply content. What no test pins is the **text of an error or a type-error string**, which is why
serve-2's `c0f5bd6` change passed its own gate. That is the load-bearing fact, and it is why this
slice needs a reflection gate rather than a golden file.

**Proven:** every documented status reachable by the fixture; every required field emitted and
decodable by a strict mirror, including `Session.directory`; `PATCH`-then-`GET` agreement in both
reachable states, with no transcript loaded on either; the greedy loaders, `loadSessionFile` and
`os.ReadFile` unreachable from `serve`; one JSON write path in the package; both reads bounded, each
with a test that discriminates; `/file/status` paths correct across modification, rename, untracked
and quoted names; allocation counts flat across a doubling of entries per session.

**Not proven, stated plainly: no byte-exact comparison is claimed, and none is possible for these
endpoints.** Specifically not proven: that the actual Swift client decodes these payloads — there is
no client on this host, and `PartStateBridge`'s tolerance for a `state` that is "a valid object or
string" (plan:174) is the plan's statement, not a measurement; that no *optional* field the client
reads is missing, because the client source was not re-read and only plan:170-179 was carried
forward; that `fileStatusDTO`'s lack of a `Status` letter is harmless to the client; that
`Session.directory` reporting a foreign cwd does not confuse the client beyond the documented 400
on echo; that `GET /session/{id}/message`'s part topology is what opencode expects, which
plan:354-356 assigns to slice 4 and open question 4 flags; and that `metaProbeBytes = 32 KiB` is
wide enough for **old** markers — a `session_info` or `session_archive` written further back than
that from the file's end is invisible, which cannot affect the `PATCH` oracle (§4.2) but does mean
a long-lived renamed session shows its first user message.

## 8. Risks

1. **A required field silently missing from a list entry.** `tokens` and `cost` are absent for
   disk-read sessions by design (§3.1); if the client treats absence as zero rather than unknown,
   the phone shows a cost of 0. plan:167-168 states absence is tolerated; the manual gate before
   slice 6 (plan:332-334) is where that is confirmed with the real app.
2. **The 32 KiB tail bound is visible to the user.** A session renamed or archived long ago and
   then grown past the bound reports no name and shows its first user message; a first user message
   that is only an image has no title fallback at all. The bound cannot make `PATCH` and a later
   read disagree (§4.2), so this is staleness, not incoherence.
3. **Two append implementations for one file format.** `Session.AppendEntry` (via
   `SetSessionName` / `Session.AppendCustomEntry`) and `SessionManager.RenameSession` /
   `AppendCustomEntry` must frame records identically. They do today — same
   `fmt.Fprintf("%s\n")`, same encoder — and §5.4's note about the differing `ParentID` is the
   place a future edit would break it. A shared golden-framing test across both is deliberately not
   added: `AGENTS.md` forbids change-detector tests, and the observable consequence is a file
   `sessionMeta` cannot parse, which the existing read tests would catch.
4. **`git status --porcelain=v2 -z` is a second implementation of a format wopr already parses.**
   The `-z` variant is not a superset of the line variant's needs, and keeping the two apart is
   cheaper than a shared abstraction that must serve both. The cost is a divergence if git changes
   the format; the mitigation is the four-case fixture test of §5.14's three facts.
5. **A test that cannot fail.** The per-DTO mirrors must use non-pointer required fields and assert
